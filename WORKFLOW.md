## Current stock-only server boundary

After an OS crash, preserve the dump/events and establish its actual driver/
process/stack before blaming the GPU or client. Matching symbols are required;
a wrong-symbol bucket is not a diagnosis. Desktop mapped-drive visibility is
not LocalSystem service access. Verify exact recording/fixture readability in
the service scope and actual capture bytes increasing before consumer gates.
Restore only the already configured exact mapping through authorized OS work;
never guess share credentials or weaken firewall/SMB policy. Record any
one-shot helper removal and preserve stock hashes/settings. Shared OpenDCT
may retain a crash-stuck upload/encoder lock even after Windows restarts:
inspect its existing logs first; never restart a shared capture service without
fresh all-owner activity guards and explicit authority for that interruption.
Delete-on-close marker proof covers process termination, not guaranteed cleanup
after a kernel crash. Distinguish pre-boot dead markers from new-run ownership;
retire only proven task-owned remnants recoverably, never a live/foreign lease.

For Windows caption capacity failures, distinguish pending reservations from
orphaned active job markers. Record redacted slot PID/port/age and exact live
process ownership; do not increase the pool or delete a different owner's
claim from the Android client. The canonical windows_caption_lease_test.cpp
uses the actual claim implementation; WindowsCaptionLeaseProbe.java verifies
Java8 visibility/readability and forced-stop removal, with an unrelated file
preserved. Run against a task-owned scratch pool, never the live plugin pool.

## Task fix and server-boundary policy

Apply this policy to every task workflow, including dependency fixes across
Vibe repositories. Fix and test necessary plugins and update the test-server
plugin without asking again solely for repository-boundary approval.

Prefer the Android client, then a stock-compatible plugin. Change non-stock
`.232` Core only for a proven production defect that neither can correct;
document the API gap and alternatives, keep optional negotiation and safe
stock/older-client fallback, and run affected compatibility tests. Never patch
Core merely to simplify testing.

Stock `.175` installation changes are limited to plugin installation/update.
Do not modify its stock Sage.jar, stock FFmpeg, Core binaries, or server
installation/configuration files. Preserve user settings, recordings and
unrelated clients; reversible supported SageTV playback APIs remain allowed.

Non-stock `.232` restarts are authorized for task updates without asking
again; coordinate them with active test guards and preserve data/settings.
  Always ask the user before restarting stock `.175`, even when it appears idle,
  unless an explicit user-granted bounded restart window is active. Record
  its UTC expiry in the task/handoff, and check expiry and revocation before
  every restart. After expiry or revocation, ask again; stock files stay protected.

Update owning TASKS.md, linked dependencies and the workspace suggested order
as work changes; move completed checkoffs into the checklist change ledger.
Test only affected gates, preserve unrelated completed matrices, and do not
stop independent authorized work for a status question or a dependency-only
permission request. Unrelated work, publication, destructive actions and
interruption of recordings/other users still require their own authority.

Run `dev.cmd` or `./dev.sh` with `test`, `validate`, `build`, `install`, or
`all`. Build creates Linux and Windows outputs. Install means the non-Android
MIM lifecycle/media suite; it does not enable MIM in a server.

For wrapper-only fixes with already qualified engines, run
`bash code/tools/rebuild_mim_only.sh` inside the existing unified DEV container
at `/project`. It rebuilds both wrappers with the existing toolchains and
refuses missing engines or changed engine hashes. Follow with affected
EOF/duplex/control/media/package tests and the ordinary plugin-manager update;
this is not a server installer or a substitute for physical acceptance.

Static validation derives the wrapper version from release.properties; do not
pin it to a historical public version. Raw stdin HUP is drained until actual
read EOF with queued bytes preserved. Do not restore a premature literal HUP
close merely to satisfy an obsolete source check; keep the exact EOF/duplex
behavioral regressions alongside source checks.

The MIM mapping suite includes `run_qsv_caption_queue_tests.py` against its
freshly compiled wrapper. Match the removed legacy token `-async ` exactly;
do not reject the distinct supported `-async_depth` option by substring.
It also runs `run_mpegts_probe_tests.py` against that exact fresh wrapper:
known TS discovery floor, larger/auto budgets, no guessed FPS, unchanged Copy/
stdin/non-TS and INI hash. For a real short-probe failure, compare the same
engine/input/options with one discovery variable changed;90kHz TS timebase is
not90kFPS. Cache presence does not inject metadata into the encoder. Preserve
actual Source cadence (including supported field-rate deinterlacing), rather
than hiding discovery errors by forcing FPS, switching GPUs or editing INI.
`run_qsv_seek_probe.py` is an explicit bounded idle-stock232 installed-engine
diagnostic, not a routine release matrix: preserve same-command before/after
evidence and inspect actual exit/output/GPU/caption/clock results. A baseline
PASS cannot erase an intermittent crash. Decoder-side A/53 names differ by
FFmpeg version; validate the reported side-data spelling before claiming loss.
The Android production-menu gate's optional `--fallback off --native-qsv-check`
reuses public owned-clock/FLUSH seeking; validate its trace before EOF retires
custody. Use its scoped capture-ready marker and an absolute host capture
output path. Do not repeat completed HLS/Web/adaptive matrices for this scoped
ordinary-Fixed queue change.

Put changed-files ZIPs in `artifacts/downloads`, use `update.cmd`/`update.sh`,
and create handoff packages with `create_ai_handoff_zip.cmd`. The sibling build
environment's `WORKFLOW.md` defines package verification and resume behavior.
